# Contact backend

The contact endpoint is a Cloudflare Pages Function at `POST /api/contact`. It validates and normalizes the request, applies anti-abuse checks, and sends a categorized HTML-safe message directly to Telegram. It does not log submitted personal information or persist contact messages.

## Cloudflare configuration

Set these encrypted production secrets/variables in **Workers & Pages → project → Settings → Variables and Secrets**:

- `TELEGRAM_BOT_TOKEN` (secret): token generated by BotFather.
- `TELEGRAM_CHAT_ID` (secret): the private destination chat ID. Start a conversation with the bot before testing.
- `CONTACT_ALLOWED_ORIGINS`: comma-separated exact site origins, for example `https://example.com,https://www.example.com`. Do not use wildcards.
- `TURNSTILE_SECRET_KEY` is a future integration option. **Do not configure it with the current UI**, because the client does not render a Turnstile widget or send `turnstileToken`; setting it now would reject every genuine submission.

Optionally create a KV namespace and bind it as `CONTACT_RATE_LIMIT`. Without it, the function uses a capped in-memory best-effort limiter per runtime instance. KV improves coverage, though KV rate limiting remains best-effort rather than strongly atomic.

Never expose `TELEGRAM_BOT_TOKEN` or `TELEGRAM_CHAT_ID` through Vite variables, source code, Git, client responses, or browser requests. Use `.dev.vars` (ignored by Git) only for local `wrangler pages dev` runs.

## Request contract

Send JSON with `Content-Type: application/json`:

```json
{
  "category": "website",
  "name": "Example name",
  "contactMethods": ["telegram", "email"],
  "contactDetails": {
    "telegram": "@example_user",
    "email": "person@example.com"
  },
  "message": "A meaningful message of at least ten characters",
  "projectType": "portfolio",
  "budget": "optional value",
  "timeline": "optional value",
  "company": "optional value",
  "role": "optional value",
  "locale": "fa",
  "website": "https://example.com/project",
  "honeypot": "",
  "formStartedAt": 1720000000000
}
```

Allowed categories are `website`, `collaboration`, `employment`, `consultation`, and `other`. You may select one or more contact methods from `email`, `phone`, `telegram`, `whatsapp`, and `other`; every selected method must have its own validated value. The server rejects duplicate methods, unknown methods, and contact-detail keys that were not selected. The optional `website` field is a legitimate related link and accepts only complete HTTP(S) URLs. The hidden `honeypot` field must remain empty. Set `formStartedAt` to `Date.now()` when the form is shown; submissions faster than 1.2 seconds or older than 24 hours are rejected.

The endpoint accepts at most 16 KiB, requires an exact same-origin or configured Origin, rejects cross-site Fetch Metadata, escapes Telegram HTML, times out third-party requests, and returns generic operational errors. Client validation is only for usability; server validation is authoritative. If a Turnstile widget is added later, send its token as `turnstileToken` and only then configure `TURNSTILE_SECRET_KEY`.

## Responses

- `200 {"ok":true}`: delivered (or silently discarded honeypot spam).
- `400`: invalid fields/timing or failed optional Turnstile.
- `403`: disallowed/missing Origin or cross-site browser context.
- `413` / `415`: oversized or non-JSON request.
- `429`: rate limit reached.
- `502`: Telegram is unavailable or secrets are not configured.

Do not display upstream details to users. A suitable generic UI message is “ارسال انجام نشد؛ کمی بعد دوباره تلاش کنید.”

## Verification

```sh
node --test functions/_lib/contact.test.js

```
